### Prototype

**Own the design decision. The prototype is an instrument for learning; the real build follows Feature.**

1. Name the unresolved question and the observation that can settle it. Use the existing brief and decisions. A read-only investigation stays read-only; if the answer is already established, continue the implementation instead of inventing another experiment.
2. Read the canonical [prototype skill](../../prototype/SKILL.md). Choose its logic, UI, or interaction branch and apply its context criteria. Use the real host when context matters and scratch when the experiment is independent. Match fidelity to the decision, including polished timing when feel is the uncertainty.
3. When references would resolve an open visual direction, use the reference study in [creative direction](../../creative-direction/SKILL.md#study-references-and-plan-assets). Reuse existing research and approved direction. Do not restart the broader workflow for a bounded experiment.
4. Build the bounded artifact. Compare alternatives only when a choice remains open. Keep mutations stubbed and unrelated production work out of the prototype.
5. Verify on the matching surface. Compare actual renders for layout, drive the behavior for interaction, and observe output or state for logic. Record evidence and limits; a screenshot cannot establish motion quality.
6. Present the result, tradeoffs, and recommendation. Capture the decision and useful artifact locally per the canonical skill. Carry its acceptance checks into **Feature**, or `architect` when the unresolved question concerns module structure.

**Reply:** the question, artifact location and run instructions, evidence, alternatives if explored, recommendation, and remaining limits. State that the prototype is temporary and which production checks remain.
