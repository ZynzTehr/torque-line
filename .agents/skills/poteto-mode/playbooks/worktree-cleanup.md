### Worktree and simulator cleanup

Apply [the canonical autonomy policy](../../../autonomy-config.md) to cleanup authorization. Use [HARNESS.md](../../../HARNESS.md) for available tool equivalents. This playbook's audit is evidence, not permission to delete.

1. **Audit locally.** Run `scripts/worktree-audit.sh [repo-path]` from the poteto-mode skill directory, or use its absolute path. It requires Git and Python 3.9 or newer and emits JSON. Optional `--base LOCAL_REF` adds ancestry information from an existing local ref. It does not fetch, query PRs, scan private transcripts, run filesystem monitor hooks, or modify Git state. A nonzero exit means an inspection failed; resolve that failure before considering the affected worktree.
2. **Inspect every candidate.** Read each exact `path`, `decision`, `files`, `reasons`, and `errors` value. `hold` protects tracked edits, untracked files, ignored files, locked worktrees, the main worktree, and incomplete inspection. `review` means only that the inspected snapshot is clean. Neither value permits deletion. Merge ancestry, a merged or closed PR, branch age, and retained branch refs cannot prove that local files are disposable or that nobody is using the worktree.
3. **Check usage and preserve work.** Establish whether the worktree belongs to an active task or another person. Use local task information or ask when this cannot be determined. Inspect all tracked, untracked, and ignored entries. Preserve needed files in a verified location outside the worktree. A new source file, an ignored database, or a local configuration file can be the only copy. Unknown contents and failed queries remain held.
4. **Confirm the concrete scope.** Present the exact paths, retained branches, files to preserve, files to discard, and any remaining uncertainty. Match them against the user's existing deletion authorization. If the user has already explicitly authorized those resources and that loss, continue without asking again. Otherwise obtain the missing path-specific authorization under the canonical policy. Broad cleanup intent and the audit result alone do not settle which user files may be destroyed.
5. **Remove only the authorized worktree.** Re-run the audit immediately before removal and stop if the contents or usage changed. Pass the exact decoded path as one safely quoted argument to `git worktree remove PATH`. If Git refuses removal or anything remains, stop and inspect the cause. Do not fall back to force removal or recursive deletion of unknown leftovers. Resolve any additional action as its own concrete scope under the canonical policy. Re-list worktrees and verify preserved files after removal.
6. **Handle other storage separately.** For simulators, runtimes, editor state, and package caches, inventory exact resources and their contents using available platform tools. Apply the same usage, preservation, and authorization checks before removal. A worktree cleanup request does not include unrelated simulator data or editor backups. Avoid blanket deletion commands.

Report the paths removed, the evidence that authorized their removal, preserved work, and held paths with their reasons. Report reclaimed space only if measured. For an audit-only request, return findings without changing anything.
